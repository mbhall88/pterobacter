# AGENTS.md

Guidance for AI agents working in this repository.

`terobacter` is one Rust crate with an internal library. It builds two equivalent executables, `tero` and `terobacter`, for classifying Enterobacter isolate assemblies. The scientific rules are frozen elsewhere; this repository implements them.

## Build, test, lint

- `just test` runs the tests twice: as a default build, then with `--all-features`.
- `just lint` runs clippy over all features and targets with warnings denied.
- `just install-check` installs into a temporary directory and checks that only `tero` and `terobacter` appear.
- `cargo fmt --all -- --check` must pass.

`tests/hygiene.rs` fails if a tracked file contains a workspace path or a private study name.

Run a single test file with `cargo test --test <name>`. Add `--all-features` for tests of the development binary.

## Layout rules

- One crate. Do not add a second crate or publish the library separately.
- Decision logic (`src/evidence.rs`, `src/reference/`, `src/decision.rs`) is pure. No terminal parsing, filesystem or process code goes in it, so a browser or GUI front end can reuse it. Files, flags and exit codes live in `src/cli.rs`, and in `src/dev.rs` for the development binary.
- Evaluation-only operations belong in the `terobacter-dev` binary behind the `dev` feature. Never expose them from `tero` or `terobacter`, and keep the feature out of default builds and installs.
- The public command is `tero [OPTIONS] <ASSEMBLY>...` with no subcommands.

## What must not enter this repository

- Research history, private data, clinical data, or paths into the research workspace.
- New evaluation outcomes. Test with synthetic fixtures and already exposed development evidence only.
- Fixtures that are not derived from frozen results. Record the derivation in the fixture's README by SHA-256, never by workspace path. The commands and full provenance stay in the research workspace.

## Agent skills

### Writing

For all user-facing documentation, GitHub issue and pull request prose, and Git commit messages, run `/avoid-ai-writing` before finalizing the text.

Issue comments and pull request descriptions written by an agent start with a line naming the agent and its exact model, for example `> **Posted by:** Claude Sonnet 5.5 (`claude-sonnet-5-5`)`.

### Commit messages

Releases and the changelog are generated by release-please from conventional commits, and it parses them strictly. Two things silently drop a commit out of the changelog:

- **Nested parentheses anywhere in the message.** Write the prose without them.
- **A subject that is not a conventional commit.** Pull requests are squash-merged, so the PR title is usually the whole commit message release-please sees. Title pull requests as conventional commits, and put the `!` there when the change is breaking.

### Issue tracker
